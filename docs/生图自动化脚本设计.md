# 生图自动化脚本设计（sprite-studio）

> v0.4 · 2026-10-22 · 已实施；v0.2 增加 ask 文案子命令，v0.3 双供应商，v0.4 收敛为火山方舟 Ark 单供应商（移除 zeakai，见 D15）
> 定位：自动化《AI生图与切图管线.md》中的「AI 生图」环节与素材入库的机械步骤，并以聊天接口起草物种文案。切图管线（`process-sprites.mjs` 的抠图/归一算法）零改动。

---

## 1. 目标与边界

**现状链路（全手工）**：即梦参考图模式逐帧生图 → 手工存 `assets-src/{物种}/` → 手改 `process-sprites.mjs` MAP → 手跑切图 → 手加 `species.ts`。

**目标链路**：

```
说一个物种名 → ask（AI 起草物种文案，人工过目）→ gen（自动生成 6 帧候选）→ 人工目检挑图（闸门）→ commit（规范化 + MAP + 切图 + 配置片段）
```

**边界（明确不自动化）**：

- **目检**。逐张目检是既定结论（管线文档 §5），脚本只负责把候选图摆好、把验收清单打印出来。
- **`species.ts` 的养护参数**。浇水/晒太阳间隔等是业务决策（见技术方案 D9），脚本只输出待填模板，人工确认后入库；也不在 AI 可生成范围。
- **物种文案终稿**。ask 只起草，人工过目后才 `--write` 入库——文案错了改一行就行，比图错了重生成便宜得多，先拦文案。
- **切图算法**。白底生成 → 抠白底管线已验证可靠，**不使用 API 透明背景**：与已入库 24 帧风格一致，少一个变量。

**形态**：确定性 Node 脚本 `scripts/sprite-studio.mjs`（零新依赖：Node ≥18 自带 fetch/FormData/Blob）。图生图与文案统一走火山方舟 Ark，`ARK_API_KEY` 一把钥匙；模型与尺寸在 `scripts/sprite-config.json` 可调。

## 2. 接口适配（均为火山方舟 Ark，`Authorization: Bearer <ARK_API_KEY>`，标准 HTTP 状态码）

### 2.1 图生图 `POST /api/v3/images/generations`

| 参数 | 取值 | 说明 |
|---|---|---|
| model | `doubao-seedream-5-0-flash-260915`（config 可改） | |
| prompt | 六段式 + 状态句（§3） | |
| image | `data:image/png;base64,…` 参考图 | 已实测可用 |
| response_format | `url` | url 24h 有效，脚本即时下载 |
| size | `1024x1024`（config 可改） | 切图管线归一 400×400，1024 足够 |
| watermark | **必须显式 false** | 默认 true，会打"AI 生成"水印 |
| output_format | **必须显式 png** | 默认 jpeg，切图管线只认 PNG |

已知限制：**无 `n` 参数**（多图是"组图"语义）——多候选按次数串行请求；**默认每帧 1 张**（出图质量稳定后为控成本，`--n` 可加）。响应为 OpenAI images 形 `data[0].url | b64_json`。

### 2.2 文本 `POST /api/v3/responses`（Responses API 形）

| 参数 | 取值 | 说明 |
|---|---|---|
| model | `doubao-seed-2-1-lite-260915` | |
| instructions | system = 文案生成规则 + few-shot（§5 ask） | |
| input | `[{role, content:[{type:"input_text", text}]}]` | |
| stream | `false` | |
| thinking | `{"type":"disabled"}` 关闭思考链 | 文案是结构化填空任务；实测调用 ~5s（不关可能超 60s） |
| text.format | `{"type":"json_object"}` | 已实测生效 |

响应取 `output[]` 中 `type:"message"` 项的 `content[].text` 拼接（关闭思考后无 `reasoning` 项，解析器对两者兼容）。

### probe 子命令

`pnpm sprite probe`：对生图、文本各发一次最小请求（1 张图 + 1 条文本，少量费用），落定响应格式/可用性，结论写 `assets-src/_probe.json`、原始响应写 `_probe-raw.json`、探测图存 `_probe-image.png`。换 key 或模型后重跑。

> 历史备注：曾同时适配 zeakai 代理（`/v1/images/edits` + `gpt-image-2.5-sunburst`，HTTP 200 业务信封报错），2026-10-22 因出图质量与 ark 相当、为简化运维移除（D11/D15）。

## 3. 提示词资产（入库，纯数据）

六段式照抄管线文档 §2.1，抽成两个数据文件，脚本只做拼装：

**`scripts/sprite-prompts.json`**（全局模板，入库）：风格段/载体段/构图段/背景段/质量段 + 6 条通用状态句。

**`scripts/sprite-species.json`**（物种段，入库——**加新物种唯一要写的文案**）：

```json
{
  "defaultRef": "assets-src/绿萝/<idle白底原图文件名>",
  "species": {
    "monstera": {
      "dir": "龟背竹",
      "name": "龟背竹",
      "emoji": "🪴",
      "desc": "高大的深绿色叶，叶缘开裂带长条形裂孔",
      "states": { "sun": "小太阳+星光+头顶开粉花" }
    }
  }
}
```

- `states` 可选：物种级状态句覆盖（ask 产物为全 6 条物种定制版）；拼装时物种级优先，缺省回退全局模板。
- `ref`：idle 主形象的风格/载体参考图，默认 `defaultRef` 指向绿萝 idle 白底原图。`assets-src/` 已 gitignore，生图仅限本机执行——与现状一致。
- 衍生帧提示词 = 「与参考图完全相同的{物种}角色」开头 + 完整六段 + 状态句，与手工流程逐字一致。
- 新条目不必手写：`ask` 子命令用文本接口起草整个物种条目，人工过目后合并进来。

## 4. 目录与产物约定

```
assets-src/
  {物种}/
    <既有原图>                     # 正式位（文件名任意，MAP 显式映射）
    _gen/                          # 脚本产物区（本地）
      idle/idle-1.png …            # 每帧一个子目录，n 张候选
      idle/idle-FINAL.png          # 人工定稿标记（见 §5）
      manifest.json                # 每张候选：prompt全文/ref/model/size/耗时/sha256
```

## 5. CLI 设计

三个子命令，公共参数：`--species <code>`、`--dry-run`（只打印将发的请求不调接口）。`package.json` 别名 `pnpm sprite`。

### ask —— AI 起草物种文案（加新物种的入口）

```
pnpm sprite ask 薰衣草
pnpm sprite ask "薰衣草，想要更梦幻的配色" --write
```

- system prompt（`instructions`）要点：只准输出 JSON；附六段式规则与已入库物种 few-shot；硬约束——风格段/载体段锁死、描述具象可执行（防跑偏写法）、状态句落在该物种自己的器官上、带"防画凶"意识。
- 输出 schema：`{ code, dir, name, emoji(建议值), desc, states{6 条} }`；**养护参数不在生成范围**（业务决策，D12）。
- 解析防御：剥代码围栏 → `JSON.parse` → schema 校验；失败带报错重试，仍失败打印原文退出。
- 默认只打印草稿；`--write` 人工过目后合并进 `sprite-species.json`，已存在 code 拒绝覆盖（需 `--force`）。`ref` 不由 AI 决定。

### gen —— 生成候选（默认每帧 1 张）

```
pnpm sprite gen --species monstera --all        # 一键：idle → 衍生 5 帧一次生成（推荐）
pnpm sprite gen --species monstera              # 只生成 idle
pnpm sprite gen --species monstera --frames happy,thirsty   # 指定帧精修
pnpm sprite gen --species monstera --frames happy --n 2    # 不满意加候选
```

- `--all`：先生成 idle，衍生帧自动以**本次新生成的 idle 候选**为参考，一条命令跑完 6 帧（免人工 FINAL 步骤）。
- 分步模式：衍生帧参考图 = `_gen/idle/idle-FINAL.png`，不存在则报错（防止拿未定稿 idle 当参考导致 5 帧跑偏）。
- idle 帧提示词显式要求"换头"防参考图植物残留；gen 结束自动 `open` Finder。
- 默认每帧 1 张（出图质量稳定，控成本），`--n` 可加候选。
- 幂等：候选文件不覆盖（追加编号）、manifest 追加写，中断重跑安全。

### commit —— 目检通过后，一键入库

```
pnpm sprite commit --species monstera [--write]
```

前置检查：6 帧各有定稿——有 `<帧>-FINAL.png` 用之；无 FINAL 但该帧**只有一张候选**时直接采用（人工触发 commit 即视为目检通过）；多候选必须显式复制选中图为 FINAL，缺哪帧列哪帧。通过后依次：

1. 各帧 FINAL 规范化复制为正式位 `assets-src/{dir}/{frame}1.png`；
2. 生成 `assets-src/{dir}/map.json`（schema 见 §6）；
3. 以子进程跑 `process-sprites.mjs <code>`（只切本物种，避免覆盖既有物种的人工修正帧）；
4. 打印 `species.ts` 待填条目模板（养护参数留 TODO 占位）；
5. 打印管线文档 §5 验收清单 + 尺寸预检结果。

`--write`：第 4 步改为直接追加进 `src/config/species.ts`（占位值必须人工调整），跑完必须 `pnpm typecheck` 并目测领养页。**默认不带 --write，只打印**。

## 6. 与既有管线的衔接（唯一需要动的地方）

MAP = 硬编码表 + `assets-src/{dir}/map.json` 合并（D13）。map.json schema：

```json
{ "species": "monstera", "frames": { "idle": "idle1.png", "happy": "happy1.png", "…": "…" } }
```

`process-sprites.mjs` 支持按物种过滤（`node scripts/process-sprites.mjs <species>`），对既有 24 帧零行为变化。硬约束 3 的「三步」依然成立，只是机械部分由 commit 代办。

## 7. 风格一致性策略

- 图生图天然是参考图模式，等价替代即梦「角色参考」，一致性方法无缝平移。
- idle 用已定稿物种白底原图做参考（花盆脸载体锁定）；衍生帧强制用本轮 idle（`--all` 用新生成候选，分步模式用 FINAL）。
- **seedream 对参考图服从性很强**：衍生帧提示词必须把变化拆成**「花盆脸表情 + 头顶植物状态」两处显式列出**（全局 `faces` 模板强制注入表情 + 物种 `states` 描述植物），只写植物状态会导致脸完全不变、帧间无差异（薰衣草 happy 实测教训）。
- **已知风险**：参考图里带绿萝叶，idle 换物种可能"换不干净"。缓解：idle 提示词明确「把头顶植物替换为：{desc}，不要出现参考图中的植物」；若仍漂移，该物种 idle 用即梦人工出图定稿，其余 5 帧仍走本脚本。
- 叶片数量偶有漂移按管线文档 §2.2 结论接受——210px 显示尺寸下不可见。
- commit 的自动预检只做机械项（尺寸、文件完整），观感仍靠人。

## 8. 安全与成本

- **Key**：`ARK_API_KEY` 环境变量或仓库根 `.env`（gitignore，提交 `.env.example` 模板；脚本零依赖解析）。获取：火山方舟控制台 console.volcengine.com/ark。密钥绝不写进文档或代码。
- **外发数据**：提示词与参考图会发送至火山方舟——接受。
- **成本**：图生图按成功张数计费，每新物种默认 6 帧（每帧 1 张）+ 文案 1~2 次调用；`--frames`/`--n` 可精确控制；429/5xx 自动退避重试，仅未出图请求会重试。
- **幂等**：候选不覆盖、manifest 追加，gen 中断重跑不重复计费已成功帧。
