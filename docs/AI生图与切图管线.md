## 2. AI 生图方案

### 2.1 提示词结构（已验证的六段式）

```
[风格段] Q版卡通+游戏精灵立绘+粗黑描边+平涂糖果色+赛璐璐阴影
[载体段] 陶土色圆形花盆作为身体+大圆眼睛+微笑嘴+粉腮红+小手小脚   ← 所有物种锁定不变
[物种段] 头顶植物的特征描述                                        ← 物种间唯一变量
[构图段] 正面全身构图，画面居中
[背景段] 纯白色背景，单一角色，无文字，无水印
[质量段] 高清细节
```

衍生帧 = 同一段提示词 + 「与参考图完全相同的XX角色」开头 + 仅替换表情/姿态句。

**物种段实例**（换物种只改这一句）：
- 绿萝：心形绿叶自然垂坠
- 龟背竹：高大的深绿色叶，叶缘开裂带长条形裂孔
- 多肉：胖乎乎的莲座状多肉，叶瓣肥厚果冻质感、叶尖粉边
- 仙人球：圆滚滚翠绿球体+对称竖棱+浅色小软刺（补"刺极短极软"防画凶）

**状态衍生句实例**：happy=眯眼大笑+爱心；thirsty=泪眼+叶下垂+头顶水滴；浇水=闭眼幸福+水珠+土壤变深；晒太阳=小太阳+星光（仙人球=头顶开粉花）；sleep=闭眼小圆嘴。

### 2.2 一致性方法（核心）

1. **先出主形象（idle），定稿后其余 5 帧全部以它为参考图**（即梦"角色参考/智能参考"，参考强度中高），提示词整段保留、只换表情句——不要每帧重新文生图。
2. 每帧生成 4 张挑 1，挑"表情变了但仍是同一株"的。
3. **实测结论**：主形象与衍生帧分辨率会不一致（1024/2048 混杂，切图管线已归一化）；表情之外的叶片数量偶有漂移，在 210px 显示尺寸下不可见；具象状态描述执行准确（多肉的"发皱→饱满"、仙人球的"头顶开花"都正确生成）。

### 2.3 交付约定

生成结果按物种建中文目录放 `assets-src/`（如 `assets-src/龟背竹/`），**不需要改文件名**——脚本 MAP 用显式映射表对应状态。

## 3. 切图管线（`scripts/process-sprites.mjs`）

纯 Node 零依赖，五步流水线：

```
PNG 解码（RGB/RGBA 8bit 非隔行）
→ 边缘泛洪抠白底（容差 20/通道，只删与画布边缘连通的白区 → 植株内部高光/眼白不受影响）
→ 边缘羽化（与透明区相邻的近白像素降 alpha，去白边 halo）
→ 双线性缩放统一 400×400（@2x，CSS 显示 200×200，源图 1024/2048 自动归一）
→ PNG 编码输出 src/assets/pets/{code}/stage0/{状态}{帧号}.png
```

**MAP 结构**（每帧一条）：
```js
{ dir: '龟背竹', file: '52design-xxx.png', species: 'monstera', name: 'idle1' }
```

**新物种/新帧操作**：往 MAP 加条目 → `node scripts/process-sprites.mjs` → 完成。

**已知特性**：脚下的浅色地面阴影会保留（起"落地"作用）；状态帧里 AI 画的道具（水滴/太阳/爱心）随帧保留。

---

## 4. 程序接入（自动，无需改业务代码）

1. `src/assets/pets/{code}/stage0/*.png` 由 `import.meta.glob` 自动注册（`src/lib/speciesArt.ts`）
2. 宠物窗按领养物种加载帧组（`petView.setSpeciesFrames`），无素材物种回退绿萝 + 色相偏移
3. `src/config/species.ts` 加入物种条目 → 领养页自动上架，卡片直接显示 idle 帧预览
4. 监听 `plant-changed` 事件，重新领养即时切换桌面分身

## 5. 验收清单（每批素材入库前）

- [ ] 同物种 6 帧齐全（idle/happy/thirsty/water/sun/sleep）
- [ ] 同组帧同画布、同锚点（整体构图居中即可，管线已归一）
- [ ] 抠图无白边残留、植株完整（叶片高光未被误删）
- [ ] 色板一致（同一套主色，参考图机制保证）
- [ ] 替换后跑 24h 常驻，内存无增长
